# InkTime 相框固件（ESP32-S3 + GDEP073E01）

InkTime 电子相框的设备端。每天定时唤醒 → 从服务器拉一张渲染好的 6 色图 → 上屏 →
在右下角画上电量图标 → 深睡。

**只针对 GDEP073E01 这一块屏**（7.3" 800×480 六色 Spectra 6）写死，不做多屏通用。
引脚、分辨率、调色板全部按 `kicad/InkTime.kicad_pcb` 的实际网表，**不是**照抄原项目
[dai-hongtao/InkTime](https://github.com/dai-hongtao/InkTime) 的引脚。

---

## 硬件

| 项 | 值 |
|---|---|
| 主控 | ESP32-S3-WROOM-1-N8R8（8MB flash + 8MB octal PSRAM） |
| 屏 | GDEP073E01，800×480，六色（黑/白/红/黄/蓝/绿），SPI |
| 电池 | 双节 18650 并联 3.7V |
| 电量计 | MAX17048（I2C） |

### 引脚（源码里在 `include/board.h`）

| 信号 | GPIO | 备注 |
|---|---|---|
| EPD DIN / SCLK | 13 / 14 | |
| EPD CS | 46 | S3 strapping 脚。空置时内部弱下拉=0，配合 IO0 上拉=1 → 正常启动 |
| EPD DC / RST | 17 / 18 | |
| EPD BUSY | 21 | **低 = 忙** |
| I2C SCL / SDA | 8 / 9 | MAX17048 |
| 充电中 CHRG | 2 | TP4056 开漏，**低有效** |
| 已充满 STDBY | 1 | 同上 |
| SW2 / SW3 / SW4 | 45 / 47 / 48 | 对地，靠内部上拉 |
| SW5 | 0 | BOOT 键，烧录用，固件不碰 |

> ⚠️ **IO2 是 TP4056 的 CHRG，不是 LED。** 原项目的固件在这里 `pinMode(2, OUTPUT)` 拉低，
> 那会和充电 IC 的开漏输出直接对拉。本固件里没有 `LED_BUILTIN`。

## 编译与烧录

### 先装工具

本机已装 PlatformIO Core 6.1.19，但**不在 PATH 里**。三种用法任选：

```bash
# ① 直接用全路径（最省事）
PIO="C:/Users/ROG/.platformio/penv/Scripts/pio.exe"

# ② 加进 PATH（一次管长期）
export PATH="$PATH:/c/Users/ROG/.platformio/penv/Scripts"

# ③ 或者用 VS Code + PlatformIO IDE 扩展，打开 firmware/ 目录，
#    左下角点「→」就是上传、「🔌」就是串口
```

### 烧录

```bash
cd software/firmware
"$PIO" run              # 编译（约 30 秒；首次要下工具链，几分钟）
"$PIO" run -t upload    # 烧录
"$PIO" device monitor   # 串口，115200
```

**接线**：Type-C 数据线，一头插板子、一头插电脑。

> ⚠️ **线一定要是「数据线」**。市面上大量 Type-C 线只能充电、没有数据线芯，
> 插上去电脑一点反应都没有 —— 这是最常见的坑，别先怀疑板子。

**驱动**：不需要。板子用的是 ESP32-S3 的**原生 USB**（IO19/20），走芯片内置的
USB-Serial-JTAG，Win11 免驱。设备管理器里会多出一个「USB 串行设备 (COMx)」。

**进下载模式**：通常**不用按键** —— 芯片会自己复位进 bootloader。
万一不行：按住 **BOOT（SW5）** → 点按一下 **复位（SW1）** → 松开 BOOT。

> ⚠️ 按 BOOT 这条路有个坑：IO46 既是屏的 CS，也是 S3 的 strapping 脚。
> 按 BOOT 时 GPIO0=0，而 **`GPIO0=0 + GPIO46=1` 是非法组合**。要是屏那头把 CS
> 上拉了，手动进下载模式就会失败。**真遇到就把屏拔了再烧**。正常走原生 USB 自动
> 进下载模式时不经过这条路径，不受影响。

### 全擦 / 救砖

```bash
"$PIO" run -t erase     # 擦掉整个 flash（含 NVS 里的 WiFi 配置）
```

### 命令行方式全挂了？用 esptool 手动烧

四个文件、四个地址（地址是 ESP32-S3 的固定布局）：

|---|---|
| `.pio/build/inktime/bootloader.bin` | `0x0` |
| `.pio/build/inktime/partitions.bin` | `0x8000` |
| `packages/framework-arduinoespressif32/tools/partitions/boot_app0.bin` | `0xe000` |
| `.pio/build/inktime/firmware.bin` | `0x10000` |

```bash
"$PIO" pkg install -g "platformio/tool-esptoolpy"   # 确保 esptool 在
```

用 PlatformIO 自带的 esptool 手动合并成一个 factory 镜像也行：

```bash
esptool.py --chip esp32s3 merge_bin -o factory.bin \
  --flash_mode qio --flash_freq 80m --flash_size 8MB \
  0x0 bootloader.bin 0x8000 partitions.bin 0xe000 boot_app0.bin 0x10000 firmware.bin
```

### 分阶段上板（推荐按这个顺序，出问题好定位）

板子刚焊完别一次全焊上就通电 —— 分两步走，能把「电源/主控」和「屏」的问题分开：

1. **只焊电源部分 + ESP32 模组**（LDO、Type-C、必要的电容、R1/R4 上拉）。
   烧录、开串口。能打印出 `===== InkTime 相框 ... =====` 就说明**主控和供电没问题**。
   此时没配置会进配网模式，串口会打印热点名 —— 到这一步就已经验证一大半了。
2. **再焊 Boost（MT3608）+ 转接板**，插上屏。**上电时按住 SW3** → 六色自检。
   屏要是不亮或者颜色不对，问题就锁定在屏/线序/驱动这一层，不用去查 WiFi。

第一次上电如果直接全焊，**万一屏不亮，你分不清是电源、主控还是屏的问题**。

## 按键

| 按键 | 上电时按住 | 运行中（清醒窗口 / 充电时） |
|---|---|---|
| **SW2**（IO45） | 清空配置并进入配网 | 换一张 |
| **SW3**（IO47） | **六色自检**（不联网、不睡） | 重新拉当前图 |
| **SW4**（IO48） | — | 立即刷新电量图标 |

> **深睡时按键没反应**，这是硬件的限制不是 bug：只有 IO0–IO21 才是 ESP32-S3 的
> RTC GPIO，而三个按键在 IO45/47/48 上。所以按键只在「刷完图后的 10 分钟清醒窗口」
> 和「充电模式」里有效。想立刻按键，插上充电器即可。

## 首次配网

1. 上电。没有配置时固件自动进配网模式（**不超时**，配好为止）。
2. 手机连热点 **`InkTime-XXXX`**（密码 `12345678`）。
3. 浏览器开 **`192.168.4.1`**。
4. 填：
   - **WiFi 名称 / 密码**
   - **服务器地址**：跑 InkTime 服务器那台机器的 `IP:端口`，如 `192.168.88.68:8765`，不用写 `http://`
   - **下载密钥**：必须和服务器 `config.py` 里的 `DOWNLOAD_KEY` **一字不差**
   - **每天几点换图**、**时区**
   - **充电时多久重绘一次电量**（可选，默认 20 分钟）
5. 保存 → 相框重启进正常流程。

之后想改配置：**上电时按住 SW2** 再进配网。或者把路由器改到它连不上，它也会自动进配网。

## 一次开机做了什么

```
判上电按住的键（SW3 自检 / SW2 清配置配网）
  → 连 WiFi（失败 → 进配网；再失败 → 睡 30 分钟重试）
  → NTP 对时
  → 读 manifest（先试 portrait，没有再用 landscape）
  → 下载 photo_<n>.bin → 合成电量图标 → 全屏上屏（约 40 秒）
  → 上报设备状态给服务器
  → 插着充电器 ? 充电模式（保持清醒，每 N 分钟重绘电量，拔电即退出）
                : 清醒 10 分钟（等按键）
  → 深睡到下一个「每天几点换图」时刻
```

拿不到图时**不会白等一天** —— 睡 30 分钟后重试。

## 与服务器的契约

```
GET /static/inktime/<DOWNLOAD_KEY>/GDEP073E01/<方向>/manifest.json
GET /static/inktime/<DOWNLOAD_KEY>/GDEP073E01/<方向>/photo_<n>.bin
POST /api/next                  ← 「换一张」时请服务器重渲染
POST /api/device/report         ← 上报电量/RSSI/固件版本
```

- `<方向>` 只有 `portrait`（480×800）和 `landscape`（800×480）两种
- **`count` 是该方向实际的张数，不保证是 5**，序号 `0..count-1` 连续；某个方向的目录
  可能整个不存在（那天该方向一张都没选中）
- `battery_slot` 是服务器渲染时给电量图标留的白底区坐标。**固件按它画，不硬编码** ——
  以后服务器改版式，固件不用重编
- 服务器对 **密钥错误**和**文件不存在**都返回 404，光看状态码分不出来

## 排障

| 现象 | 先查什么 |
|---|---|
| **屏全白/全黑/不刷新** | 上电按住 SW3 进六色自检。色块不对 = 引脚/线序/驱动问题，别去折腾 WiFi |
| 色块颜色对但顺序乱 | `epd_display.cpp` 的 `kGxColor` 映射表。GxEPD2 的面板字节序是 `黑0 白1 绿2 蓝3 红4 黄5`，和服务器调色板顺序**不是**一一对应 |
| 蓝、绿被画成白色 | 同上 —— 这正是原项目固件的 bug（只写了 4 个 case，其余 default→白） |
| **一直拉不到图** | ① 服务器上 `output/GDEP073E01/portrait/` 里有没有东西 ② **下载密钥对不对**（错了也是 404）③ 服务器地址/端口 |
| 显示的还是昨天的图 | 服务器当天没渲染成功，或相框没唤醒。串口看 `[拉图]` 那几行 |
| 按键没反应 | 深睡中本来就按不动（见上方按键表）。插上充电器再试 |
| 充不上电 / 电量一直 `--` | MAX17048 没应答。串口看 `[电量]` 那行 |
| **烧录后不启动** | 多半是 IO45 被内部上拉带着复位了。详见 `board.cpp` 的 `releaseStrappingPins()` |
| WiFi 连不上且进不了配网 | 上电按住 SW2 |
| **日志全正常、引脚全对，屏就是一片黑** | **ESP32 模组虚焊**。实测踩过：网表核对无误、固件无误、串口日志一路正常，但 SPI 信号根本出不去。**补焊模组**即可 |
| **六色色带颜色全乱**（红显灰、黄显蓝…） | 颜色码表，见下面「颜色码表」一节 |
| 上屏耗时只有 1~2 秒 | 屏没响应。正常应约 30~40 秒 —— 这个数是最快的判据 |

### 颜色码表（踩过的坑，别再改回去）

**GxEPD2 的 `GDEY073D46` 驱动内部用的颜色码，和我们这块 GDEP073E01 不是一套：**

| 面板码 | GxEPD2 以为的 | GDEP073E01 实际的 |
|---|---|---|
| `0x00` | 黑 | 黑 |
| `0x01` | 白 | 白 |
| `0x02` | 绿 | **黄** |
| `0x03` | 蓝 | **红** |
| `0x04` | 红 | **无定义**（厂商头文件里这行是注释掉的） |
| `0x05` | 黄 | **蓝** |
| `0x06` | 橙 | **绿** |

只有黑白两色是相同的。所以 `epd_display.cpp` 里那张 `kGxColor` 表**右边一列的名字看着别扭是故意的** —— 要出红色就得传那个"名叫 `GxEPD_BLUE`、码却是 `0x03`"的常量。照着名字"修正"回去就是又一次颜色错乱。

权威来源：厂商 `waveshare/e-Paper` 仓库的 `EPD_7in3e.h`（`EPD_7IN3E_YELLOW 0x2` / `RED 0x3` / `BLUE 0x5` / `GREEN 0x6`，`ORANGE 0x4` 被注释掉）。

> 顺带：几何和初始化序列是**对得上**的 —— GxEPD2 那份 `_InitDisplay` 里 `TRES = 0x0320 × 0x01E0`（正是 800×480），命令串和厂商 `EPD_7in3E_init` 逐字节相同，只有 `0x01/0x06/0x30` 三处调参不同。所以驱动不用换，只改这张颜色表。

### 排线插反的后果

实测踩过：**转接板和板子之间那根排线插反了**。引脚顺序会整个镜像，后果不是"不工作"这么简单：

- `+5VEPD`（5V）会打到屏的 **RES#** 上（规格书里 VDD 绝对最大只有 3.6V）
- 板子的 `RST` 引脚反过来要去顶转接板的整个 VCC
- **GND 和 BUSY 对调** → 转接板没有真正的地

插之前对着丝印确认 1 脚方向，别只看排线颜色。

## 上板调试实录（2026-09-13 首板 → 2026-09-19 端到端跑通）

**当前状态：相框能用了。** 插 Type-C → 连 WiFi → 对时 → 拉图 → 六色上屏，
一天一次，跑完进清醒窗口再深睡。

### 踩过的坑（按"下次会再踩"的严重程度排）

#### 1. 刷屏时必须 `yield()`，否则中断看门狗复位 ★★★

`epdShowBuffer()` 的绘制回调里那句 `if ((y & 0x0F) == 0) yield();` **不是优化，是不加就会复位。**

GxEPD2 的分页绘制会把回调**连跑 4 遍**（每页一遍），每遍 800×480 = 38 万次
`drawPixel`，全程一次不让出 CPU。后果：

```
rst:0x8 (TG1WDT_SYS_RST)      esp_reset_reason() = 5 (INT_WDT)
Guru Meditation Error: Core 0 panic'ed (InstrFetchProhibited)
```

它伪装成过很多别的东西：**板子每 5~21 秒重启一次、屏幕永远刷不完、USB 反复掉线、
"一连热点就重启"** —— 全都指向"供电不足"，全都不是。参考项目那份 13.3" 固件在
同一位置也有这句 `yield()`，照抄就对了。

> 另：`showIndex()` 原来无条件 memcpy 出第二块 384KB 缓冲（`g_work`）。
> 服务器没给 `battery_slot` 时那块缓冲毫无用处，白占 PSRAM、白做一次大 memcpy。
> 现在改成**按需分配**。栈也从 8KB 加到了 32KB（`-DARDUINO_LOOP_STACK_SIZE=32768`）。

#### 2. ESP32 模组虚焊 ★★★

症状：**串口日志全正常、网表逐脚核对无误、固件无误，屏就是一片黑。**
补焊模组后立刻好转。这类"什么都对但就是不工作"的，先做通断测试。

#### 3. 转接板与板子之间的排线插反了 ★★

不是"不工作"那么轻：`+5VEPD`（5V）会打到屏的 **RES#** 上（规格书 VDD 绝对最大 3.6V），
板子的 `RST` 引脚反过来要去顶转接板的整个 VCC，而且 **GND 和 BUSY 对调** ——
转接板等于没有真正的地。插之前对着丝印确认 1 脚方向，别只看排线颜色。

#### 4. 颜色码表和 GxEPD2 不是一套 ★★

见上文「颜色码表」。**能亮 ≠ 颜色对**，必须逐条核色带。

#### 5. 配网页的 AP 起不来的两种写法 ★

- **不要用 `WIFI_AP_STA`**：STA 的每次扫描都会把射频从 AP 的信道拽走，客户端关联时
  撞上就失败 → "热点时有时无、连不上"。改成**先扫一次拿列表 → 切纯 AP → 固定信道**。
- **别在每次加载页面时扫描**：那是把上面那个问题放大 —— 每刷一次页面就拽一次。

#### 6. 排障时最有用的几个探针

| 探针 | 在哪 | 看出什么 |
|---|---|---|
| **`esp_reset_reason()`** | 开机 banner | **一刀切开"欠压"和"崩溃"** —— 我在这上面走过大弯路 |
| **上屏耗时** | `epdShowBuffer` | 正常 30~40 秒；只有 1~2 秒 = 屏没响应 |
| **BUSY 三态读数** | 自检开头 | 无上下拉/上拉/下拉各读一次，跟着我们走 = 线是浮的 = 屏没驱动它 |
| **密码指纹** | 配置行 `pass=(len=?,fp=????)` | 凭"已设置"分不清"密码改了但还错"和"压根没存进去" |
| **分页进度** | 每页一行 | 只到"开始"没"第 N 页" = 卡在那页；全打完没画完 = 卡在等 BUSY |
| **配网心跳** | 每 20 秒 | "当前连着 N 个客户端" 从 0 变 1 = 手机真连上了 |

### 🔴 硬件上还没解决的（不是固件的事）

1. **电池保护电路接错了 —— U4(DW01A) 的 pin 2 和 pin 6 反了。**
   pin 6 (VSS/GND) 接到了系统 GND，应该是**电池负极 B−**；pin 2 (CS) 接到了 B−，
   应该接检测点。后果：DW01A 的基准错了，CS 相对 VSS 有 1.5V（远超它 0.1~0.2V 的量程），
   **被判定成短路 → 锁死放电管 → 电池有电却供不上来**。
   **现在整机只能插 Type-C 用**。v2 必须改板；临时可飞线（割断 pin 6 到 GND 的铜皮、
   接到电池负极），但**没装电池时不能短接 B− 和 GND**（会把 TP4056 输出短路）。
2. **深睡实际电流未知** —— 转接板没有 PWR_ON、MT3608 的 EN 也没接 GPIO，**屏永久带电**；
   规格书里待机/深睡电流那栏是**空的**。这个数不出来「一天一充能撑多久」就无从谈起。
3. **电量计读不到** —— MAX17048（U7）没应答。查 U7 焊接、I2C（IO8=SCL / IO9=SDA）。

### 🔶 还没验证

- **`setRotation` 的横用方向** —— 竖用（480×800，rotation 1）已实测通过（照片正常上屏）。
  横用那条路（800×480，rotation 0）还没在真屏上看过。
- **BS0 / BS1 的电平** —— 规格书 p6 和 p13 自相矛盾。实测能用，跳线应该是对的，但没细究。
